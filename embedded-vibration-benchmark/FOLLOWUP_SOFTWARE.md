# Reproduce the first three follow-up investigations

Run from the project folder with `requirements-advanced.txt` installed and the
verified `data/arq_all_trials.npz` plus original `advanced/results/` available.
The original study's checkpoints/predictions and exported Arduino models are
inputs to the audit; follow-up scripts do not replace them.

```sh
python3 -m unittest discover -s tests -p 'test_followup*.py' -v
python3 -m followup.experiments
python3 -m followup.failures
python3 -m followup.analyze
python3 -m followup.observation
python3 -m followup.plots
python3 -m unittest discover -s tests -v
```

The experiment script runs the fixed 108 candidate and 12 shuffled-training fits.
It trains all configurations and records validation choices before test inference
within each object/seed fold. It then reproduces the frozen original checkpoints
and evaluates three shuffled-history draws plus reversed history. Metadata becomes
`complete` only after all phases pass and original artifact hashes are unchanged.
The main analyzer rejects incomplete, duplicated or unpaired data and validates
selected configurations against the saved validation choices. A repeated run
overwrites only `followup/results/`, with deterministic seeds/settings; numerical
reproduction can vary across library versions and machines. No hardware result
is generated by any command here.

| Artifact | Contents |
| --- | --- |
| `FOLLOWUP_PROTOCOL.md` | Fixed questions, grid, tie rules, exclusions and stopping condition |
| `followup/results/metadata.json` | Environment, protocol hash, splits, frozen-source hashes and completion |
| `*_choices_before_test.json` | Fold's candidate validation details and choices before test |
| `*.pt`, `*_history.json` | All 120 trained configurations and histories |
| `robustness_predictions.csv`, `robustness_summary.csv` | Raw fixed-grid and shuffled-training results |
| `selected_predictions.csv`, `selected_error_rates.csv` | Validation-selected comparison and error rates |
| `temporal_diagnostics_*.csv` | Frozen checkpoint order controls, draw IDs and decision changes |
| `analysis.json`, `macro_grid.csv` | Paired whole-trial intervals and descriptive sensitivity grid |
| `observation_spans.csv`, `observation_summary.csv` | Original timestamp support durations, not physical delay |
| `followup/failures/` | Original prediction audit, context/age strata, per-trial errors, feature shift and provenance |
| `followup/figures/` | Four inspected PNG/SVG figures labelled as host-recorded results |

Sources are `public_recorded_host_followup`, `public_recorded_host_error_audit`
and `public_recorded_timestamp_audit`. None belongs in `hardware_results/`.
The existing board instructions still refer to the original frozen 32-sample
export, not the validation-selected follow-up models. Training wall time is not
inference performance. Larger observation windows also have a larger data-support
cost even if their inference is fast.
